# Revelation RT v2：清晰阴影与染色玻璃透光

修改日期：2026-10-26。基于 Revelation；原作者 HaringPro，Apache-2.0。所有修改文件均添加了修改声明。原始 LICENSE、素材与致谢保留。

## 安装与起始设置

1. 使用 Minecraft **1.21.1 Fabric**，以及支持 `REVERSED_CULLING` 的 Iris 和配套 Sodium。已只读确认你的实例使用 **Iris 1.8.14-beta.1**，其包含本次使用的功能；v2 仍需在游戏中验收。
2. 把交付的 `Revelation-RT-v2-Glass.zip` 放进对应实例的 `shaderpacks`。ZIP 根目录直接包含 `shaders/`，无需解压，也不要放到 `resourcepacks`。
3. 在 Iris 中选中光影，进入光影设置的配置预设，选择 **RT - 5060 日常**。
4. 从 1920×1080、100% 渲染比例起步，按游戏实测帧率调整。这里没有承诺目标 FPS；笔记本功耗、场景和材质包都会影响结果。
5. 参数入口为 **光照 → 软件光线追踪（实验）**。开启路径追踪时，同时保持“全局光照”和 SVGF 开启。粗糙材质反射需要对应材质具有反射属性；PBR 材质包须开启 PBR 资源包支持。

| 预设 | 每像素路径 | 漫反射反弹 | 每条射线步数 | 粗糙反射样本 | 手持阴影步数 | 单段最远距离 |
|---|---:|---:|---:|---:|---:|---:|
| RT - 5060 日常 | 2 | 2 | 48 | 2 | 32 | 64 格 |
| RT - 超高画质 | 4 | 3 | 64 | 4 | 48 | 96 格 |
| RT - 截图 / 电影 | 8 | 4 | 96 | 8 | 64 | 128 格 |

间接光每帧在宽高各一半的分辨率追踪，再使用现有 SVGF、法线/深度引导升采样和 TAA 重建。上述路径数不等于最终全分辨率的独立样本数。日常档把历史上限设为 32 帧，减少长时间累积造成的光照迟滞。截图档计算量很高，不建议直接视为 RTX 5060 的实时档位。

默认代码已开启增强；显式选择日常预设还会应用较短的历史长度与较低的原版光照混合。`旧版间接光` 切回原版 SSILVB 算法，仍保留本次公共射线和手持光源代码。需要逐字节还原时，使用旁边的原始备份 ZIP。

## 实现内容

- **漫反射路径追踪**：余弦加权半球采样，逐段求交，最多四次反弹；命中后使用材质反照率和金属度衰减吞吐量，传递可见表面的色彩。每次命中的直接光只添加一次。
- **独立直接光历史**：`colortex5` 保存不含路径追踪间接光和间接反射的表面直接出射光，A 通道保存视空间深度；下一帧重投影到 `colortex10`，根据屏幕范围、深度、历史重置和帧号判定有效性。避免用“已经含 GI 的最终图像”继续显式反弹而重复计光。新出现表面暂用自发光与原版方块光场估计。
- **公共射线求交**：透视投影下的深度线段检测、近平面与视口裁剪、以格为单位的厚度、二分细化；防止轴平行方向除零、非法纹理坐标、零长度射线和超过点光源终点的误遮挡。反射和启用后的追踪折射也使用该实现。
- **粗糙反射**：对粗糙表面使用多条 GGX 可见法线采样射线并平均；镜面只保留一条，沿用原版反射过滤。水面沿用原有反射流程并使用增强后的求交器。
- **手持照明**：左右手分别处理，近似手部位置、有限作用范围、反平方形式的距离衰减、法线朝向、GGX 高光和可见不透明几何遮挡；默认光源半径为 0，采用固定求交采样形成清晰稳定的阴影；启用非零半径时使用固定圆盘多采样，不再逐帧随机抖动。手持阴影使用独立的 0.04 格厚度和几何法线偏移，避免 PBR 法线影响阴影偏移。火把暖色、灵魂火焰青色、红石红色、常见白色发光物体有独立颜色。物品本身的光照等级由 Iris 提供，本次没有修改游戏行为或为原本不发光的物品强行赋光。
- **稳定性**：间接光采用亮度限幅抑制高亮噪点，SVGF 时间累积增加邻域方差裁剪和亮度突变响应，丢弃失效历史。

## 必须了解的边界

这是 **OpenGL / Iris 下的软件屏幕空间光追**。它无法直接调用 RTX 的硬件加速结构或光追管线，包含专门用于玻璃透射的局部体素网格，没有完整世界不透明几何或 BVH。屏幕外、被前景遮住的表面、物体背面均不能准确参与追踪。未命中时使用天空环境与原版亮度信息兜底，转动视角时仍可能出现缺失或变化。

本实现使用不含第一人称手模型的不透明深度；染色玻璃透射已由局部数据与日月阴影图实现；完整折射光路、焦散、其他玩家的动态发光物品仍未实现。手持光源位置是第一人称近似，不能声称精确跟随挥手动画或第三人称人物手部。直接光缓存的高光来自上一帧观察方向，因此多反弹结果仍是实时近似，并非离线无偏路径追踪。

间接光限幅、深度厚度、历史裁剪会引入偏差。提高采样和反弹次数会增加计算成本，但不能弥补缺失的几何。若目标是稳定的屏幕外照明与反射，下一阶段需要单独实现世界体素/BVH 数据采集、更新与追踪，或修改渲染器接入硬件光追。

玻璃网格额外占用约 1 MiB（64³ × R32UI）和一个 16 字节状态缓冲。附近没有玻璃时使用快速返回，避免对每个像素遍历空网格。原有 RT 增强新增两张 RGBA16F 全分辨率缓冲，单份合计约 31.6 MiB（1080p）或 56.3 MiB（1440p）；Iris 的前后缓冲可能使实际分配增加，不包含原版缓冲和驱动开销。

## v2 的玻璃透射范围与使用

“染色玻璃透射着色”默认开启。支持 16 色整块染色玻璃、16 色染色玻璃板、透明玻璃及透明玻璃板。手持火把到表面的路径穿过红玻璃后得到红色偏光；经过多层时逐层乘以透射率，同时影响进入间接光的光能。玻璃板使用中心柱与四方向连接臂的实际并集，不把整格空气也染色。

实现方式：每帧在 `begin` 清空一个 64³ R32UI 网格；`shadow` 顶点阶段用 `at_midBlock` 记录玻璃位置、颜色与连接形状；`shadow.culling=reversed`、`voxelDistance=32` 保留玩家附近的网格输入；手持光与 GI 光路用三维 DDA 穿行网格，并根据实际穿透长度执行吸收。日月光在已有彩色阴影图中使用相同颜色参数。

局部网格覆盖相机整数位置附近每轴 ±32 格，范围内包括屏幕外被提交的玻璃几何。它依赖已加载且提交给阴影阶段的区块网格；不代表获取了完整方块数据库。完全没有渲染面的内部玻璃可能缺失，范围外的手持光和 GI 玻璃着色没有保证。日月光仍受阴影图距离、分辨率和单层透射记录限制。模组自定义玻璃需要额外映射材质 ID。

这次提供的是受光表面的彩色照明，没有增加火把在空气中可见的体积光束；透光着色也不等于聚焦焦散。

新文件名会避免旧 `Revelation-RT-Experimental.zip.txt` 中保存的参数覆盖新的清晰阴影默认值。进入 **光照 → 软件光线追踪（实验）**，保持“染色玻璃透射着色”开启，“手持光源半径”设为 **0.0**。如果想要少量柔化，可用半径 **0.01–0.02**、固定采样 **4**；更大的半径仍会产生更宽半影。

## 已完成的验证

验证机器：NVIDIA GeForce RTX 5060 Laptop GPU，OpenGL 4.6，驱动 616.92。验证是隐藏窗口内直接调用显卡驱动完成的，不是仅用文本检查代替编译。

- 对新增及受影响的主世界/下界程序，以实际预设和 PBR、彩色手持光、缩放、无 SVGF、DH 分支做编译和独立程序链接。
- 在真实 GPU 上执行生产求交器，对已知深度平面和全天空场景检查正反向求交、有限距离、平行射线、零向量、无效起点与屏幕边界。实际结果保存在 `validation/gpu-validation.json`。
- 对实际手持照明函数验证硬阴影遮挡、跨帧一致性，以及默认边缘不会输出随机灰阶阴影带。
- 验证 24 项玻璃行为，包括红/蓝颜色、叠层乘法、有限光源终点、清空与写入、负坐标相机、斜穿路径长度和玻璃板空隙/连接臂。
- 检查所有入口的 include 图、原协议一致性和交付 ZIP 内容。

**尚未验证**：Minecraft 1.21.1 + Iris 实际资源绑定/完整管线运行、游戏内截图、噪点和拖影的视觉验收、平均 FPS / 1% low、显存峰值、第三方模组组合。驱动编译和受控射线测试通过，不能等同于上述项目已通过。

在具备 OpenGL 4.6 兼容上下文的 Windows 机器复现驱动验证：

```powershell
python -m venv .validation-venv
.\.validation-venv\Scripts\python -m pip install -r scripts/requirements-rt-validation.txt
.\.validation-venv\Scripts\python scripts/validate_rt.py --report validation/gpu-validation.json
```

脚本只对目标配置进行独立编译/链接，不复刻 Iris 的着色器转换器，不运行 Minecraft；DH 等可选分支的编译通过也不等同于模组联机验证。

## 游戏内验收顺序

1. 原版材质、日常预设，在主世界与下界切换，检查 Iris 日志中是否有编译、链接、图像或缓冲绑定错误。
2. 暗室内用白色地面和红/绿墙面对比增强 GI 与旧版 GI，检查色彩反弹；缓慢转动镜头，观察屏幕边缘缺失。
3. 主手和副手分别拿火把、灵魂火把，绕过石墙并切换物品，检查颜色、衰减、遮挡和响应；屏幕外遮挡不作为已实现能力。
4. 使用有真实粗糙度/金属度数据的 PBR 材质，比较粗糙反射采样 1/2/4，检查高光和噪点。
5. 在水边、雨天、快速转身、进出洞穴、传送和改变窗口大小时检查 NaN 黑斑、闪光和历史拖影。
6. 暗室内先放白墙，在火把与墙之间依次放红/蓝/绿玻璃，检查墙上色斑；再测试两层不同色玻璃、连接/未连接玻璃板、移除玻璃和移动相机后的更新。
7. 固定场景、时间、分辨率和视距，分别记录三个预设的帧率、1% low 与显存。对 5060 优先降低路径数/反弹数；必要时降低渲染比例。
