# Revelation RT v9.2：每盏灯一次投影

2026-10-27。针对用户在 v9.1 中反馈的活板门开孔多重亮斑与低帧率。

## 为什么 v9.1 仍然奇怪

固定四点消除了采样的逐帧随机性，却把一个光源近似成四个离散的虚拟光源。对活板门这种开孔遮挡物，每个采样点都会投出一份错开的图案。稳定性测试只能证明图案不抖动，不能证明它像连续面光源的半影。

## 本版行为

- 极高和光线追踪档都默认使用**每盏灯一次中心投影**。直接光路径在编译时选择单射线分支，不构造圆盘采样基底，不再叠加四份或八份离散投影。
- 手持光源同样使用单一中心投影，保留手持位置碰撞保护。
- 保留多灯各自的阴影、活板门真实开孔、玻璃颜色吸收、GI、PBR 和半分辨率缓存。不会把所有灯合成一盏，也不会关闭遮挡来消除重影。
- 旧的面积采样保留为默认关闭的高级实验选项，中文界面注明“可能重影”。切换到极高档会明确关闭该选项和随机单采样。

这是**点光源阴影近似**：阴影会更硬，不能宣称具有完整连续面光源半影。真正平滑的面光源半影需要另一套可靠的积分与重建；本版不通过增加少量清晰投影来冒充该效果。

## 可验证的开销变化

在每盏灯、每个接收点的直接阴影计算中，极高档由四条可见性射线变为一条；手持光源由两条变为一条。没有增加新的模糊/历史图像或渲染阶段，保留半分辨率缓存。

`validation/shadow-projection-v92.json` 的计数来自给真实遮挡函数插入的 GPU 原子计数器：64×64 接收面、单灯，v9.1 为 16384 条，新默认为 4096 条。它说明这一项的射线工作量减少，**不代表整帧快四倍，也不能用来承诺实际 FPS**。

## 投影检查

`scripts/shadow_projection_v92_checks.py` 包含：

1. 发布的 v9.1 积分函数作为会出现错开投影的对照。
2. 实体方块遮挡与独立 CPU 线段/AABB 投影对照。
3. 本机原版橡木活板门模型与 PNG 的开孔几何；4096 条接收射线使用独立 CPU 线段/微体素求交，和 GPU 投影比较。
4. 32 帧静态稳定性，手持光源贡献，单灯实际射线数量，以及完整明区/阴区保留。
5. 六档/功能开关编译、Iris 选项解析、多灯、玻璃、开孔与缓存行为回归。
