# Revelation RT v5：写实日照、灯光与玻璃

目标：Minecraft 1.21.1 Fabric / Iris 1.8.14-beta.1。作者 HaringPro，Apache-2.0。
这是可测试的第五版实现，**独立 GPU 验证与 Iris 元数据解析通过不等于游戏画面验收**。本轮没有启动 Minecraft，没有测量游戏帧率。

## 使用

选择 `Revelation-RT-v5-Realistic.zip`，先用 **RT - 写实光照 / 玻璃**。
这个档位保留 1 路径、1 次间接反弹、4 个局部阴影样本，使用 2 个反射样本、32 个屏幕追踪步数，启用彩色太阳体积光，日月角半径使用原来的物理尺度 1.0。
负载过高时切回 **RT - 5060 日常**（1 个反射样本、24 步）。没有帧率保证。

## 本轮实际修改

- **太阳系统**：保留 Revelation 的大气散射、天空 LUT、云影与日照方向系统。近处太阳彩色阴影、太阳体积光改用同一个玻璃吸收模型；在最近玻璃处于已捕获网格时，沿太阳方向累计多层玻璃，避免只有最近一层着色。远处及其他透明材质继续使用原阴影图。
- **人工灯光**：火把、灯笼、营火、海晶灯、末地烛等区分发光尺寸、色彩与状态位置。手持与放置灯光均使用带近场上限的反平方衰减和光源范围末端平滑衰减。移除 v4 的 8 格外跳过遮挡及近处直接淡化遮挡；亮度控制只应用一次。
- **孔洞**：从本机原版 1.21.1 模型及纹理 alpha 生成 16³ 位掩码。局部遮挡按微体素 DDA 检查活板门、门、铁栏杆与铜格栅，覆盖 984 个状态、134 个掩码（含空掩码）。实心木质活板门仍然挡光；开关、上下半部、朝向会改变遮挡。生成数据不包含原版彩色纹理。
- **玻璃折射**：最前一块原版实体玻璃/玻璃板重建入射及出射界面，按 Snell 定律求光线方向。平行玻璃面产生与厚度相关的横向位移，玻璃板与整块玻璃不再使用相同的虚构厚度。出射发生全反射时没有透射光。
- **反射与高光**：透明表面使用 Fresnel 反射/透射分配、GGX 粗糙反射采样；补上放置灯及双手光源在玻璃、水面上的直接高光。粗糙度在光影设置的 Ray Tracing 页面调整。
- **吸收**：可见玻璃、局部灯光、太阳阴影、太阳体积光统一调用每格实际光程的 Beer 吸收。移除玻璃板的 8 倍人工密度，薄板正常入射吸收较少，侧向长路径吸收较多，多层颜色相乘。

玻璃染料颜色及灯光颜色仍为艺术标定，未进行物理照度/流明或实测光谱标定。

## 建议游戏内验收场景

1. 固定晴天、位置和曝光，在白色房间开窗。正午和傍晚分别看窗框投影、室内外亮度与太阳光束；切换时间时检查天空正常更新。
2. 在灯笼或火把与白墙之间分别插入红/蓝玻璃、两层玻璃、玻璃板。移除光源和玻璃，检查直接颜色立即消失；玻璃板正视应比整块玻璃吸收少。
3. 在小火把与白墙之间放竖起的橡木/铁活板门，墙与活板门间留 1–2 格。检查孔洞投影，再切换开关/朝向；同样用太阳照射水平活板门检查太阳孔洞阴影。
4. 通过玻璃板和整块清玻璃看棋盘墙，正视及斜视对比。观察折射位移和掠射角增强的反射，移动灯笼观察表面高光。
5. 用石墙挡住 9–14 格外的光源，绕行及转镜头，检查不再因为距离超过 8 格就直接穿墙。
6. 保持分辨率、视距、时间、天气和位置相同，对比 v4 / v5。记录稳定帧时间、平均 FPS 和 1% low；编译耗时不能代替性能。

## 已完成的验证

- `scripts/probe_rt_v5.py` 在 RTX 5060 Laptop GPU 上执行生产 GLSL：365 项行为检查，包括 81,920 条活板门像素射线、玻璃界面折射、Fresnel/全反射、连接玻璃板、负坐标捕获、清空、多层吸收、远处墙体遮挡及手持开关测试；实际渲染太阳阴影片元，验证清玻璃中央透明像素保留透射而其他镂空仍裁切。
- `scripts/validate_rt_v5.py` 编译/链接主世界与下界受影响的 RT 入口及其数据生产/使用入口，覆盖五个档位及玻璃关闭、光源关闭、追踪折射与 PBR 分支。准确计数见 `validation/build-v5.json`。
- 本机 Iris 1.8.14-beta.1 的解析器检查新开关、粗糙度选项和 RGBA16 玻璃缓冲格式。它不创建完整游戏渲染管线。
- 校验报告绑定全部光影文件与 LUT 的 SHA-256 摘要；打包拒绝过期报告，检查 ZIP CRC 与逐文件内容一致性。

运行 GPU 校验需 `scripts/requirements-rt-validation.txt` 中的 Python 依赖。生成孔洞数据：

```powershell
python scripts/generate_rt_scene.py --client "你的原版1.21.1客户端.jar"
python scripts/probe_rt_v5.py
python scripts/validate_rt_v5.py
```

## 明确边界

- 软件光追采用局部网格、阴影图与屏幕深度。附近网格为相机中心 64³ 格，每屏幕图块最多 4 灯、总数 256 灯；尚未提交给阴影阶段、未加载和网格外的遮挡无法完整重建。
- 太阳透过孔洞的几何/alpha 使用当前实际阴影图。局部灯光的孔洞位掩码来自原版，其他资源包的自定义模型/透明孔洞需要重新生成，不能保证自动适配。
- 相机折射只求最前一个玻璃单元的双界面；多层玻璃的影子吸收可以累计，但可见多层折射、复杂内部反弹、聚焦焦散没有完整求解。全反射截断透射，未追踪其后续内部反弹。
- 玻璃阴影仍沿未弯折的可见性射线累计吸收，未计算灯光/阳光穿玻璃后的聚焦和发散焦散。
- 反射及折射后的背景依赖屏幕可见深度，无法得到完整屏幕外物体。Voxy 与 Distant Horizons 的专用接口未做本轮集成验收。
- 体积光的此次改动针对太阳光；人工灯光暂未新增完整的体积散射光束。

## 依据

玻璃界面依据 [PBRT Dielectric BSDF](https://pbr-book.org/4ed/Reflection_Models/Dielectric_BSDF) 的 Fresnel / Snell 模型；厚度吸收依据 [PBRT Transmittance](https://pbr-book.org/4ed/Volume_Scattering/Transmittance)。计算任务继续按 [Iris 程序顺序](https://shaders.properties/current/reference/shadersproperties/ordering/) 顺序执行，保持天空生产者和透光网格清空入口独立。
